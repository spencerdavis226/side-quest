# Adding a card pack

1. Add card definitions and a pack definition in a module under `src/content`.
2. Import and append them to the exported `cards` and `packs` arrays in `catalog.ts`, add a loader for the pack in `loaders.ts`, and run `npm run content:manifest`.
3. Put referenced artwork under `public/art`. A card's `artwork` must be a key in the registry in `src/presentation/artwork.ts`; the shared placeholder is `art/tankard.webp`. To ship a finished illustration, add the file and a registry entry (public path plus `scene: 'painted'`) instead of branching on a card ID in `CardFace`.
4. Run `npm test` and `npm run build`. The build checks fields, IDs, membership, and resolves every card's artwork through that same registry, failing on an unregistered reference or a missing file.
5. Inspect each card at small iPhone size and enlarged text. The group should understand a rule on one reading.

Example (not enabled in the catalog):

```ts
import type { CardDefinition, PackDefinition } from '../game/types';
export const exampleCards: CardDefinition[] = [{
  version: 1,
  id: 'fireside.story',
  title: 'Fireside story',
  rules: 'Going clockwise, each person adds one sentence to a story. End after one round.',
  category: 'challenge',
  artwork: 'art/tankard.webp',
}];
export const examplePack: PackDefinition = {
  version: 1,
  id: 'fireside',
  logo: 'art/packs/fireside.svg', // One single-colour silhouette; the app tints it.
  title: 'By the fireside',
  description: 'Stories and gentle mischief for a cozy table.',
  cardIds: exampleCards.map(card => card.id),
};
```

Use stable namespaced IDs; never recycle one for an unrelated card. Supported categories: `sip`, `group`, `category`, `challenge`, and `rule`. Rules are plain text, not HTML. Keep one clear instruction. Aim for 90 characters and 18 words or less; the build flags longer copy for review and rejects rules over 120 characters or 24 words. State who acts — the drawing player, everyone, or a named subset — and how long a lasting rule lasts: the rest of the game or until the drawing player's next turn, never until the next card. Specify who starts and when the activity ends. Long text stays inside the fixed 2:3 card and scrolls within the rules panel at enlarged settings; the card never grows for content. Cards carry no illustration text: every card renders in the shared painted frame with its deterministic imprint, so authoring never blocks on art. Do not bake rule text into artwork.

The rule text scales from 26px on a phone card to 34px on a wide card at the default browser text size. Enlarged mode uses 34–42px. Review the actual rendered card at 320px and 390px viewport widths; character counts cannot predict where words wrap. Keep a short lead sentence so a group across the table can grasp the action before anyone scrolls.

Card titles have a hard authoring limit of 22 characters and 15 characters per word (the supplied sheet's `Weinerschnitzel` sets the current floor). The title starts at a size proportional to card width and shrinks only if its rendered text would exceed the two-line teal band, down to 18px. The workshop/browser fit check is still required because equal-length words can render at different widths. Existing saved titles are never shortened or renamed; unusually long legacy titles remain scrollable.

Overlapping packs share a card by ID; it enters the shuffle pool only once. New packs are off until selected. Pack choices affect the next game; an active session retains its snapshot. Keep previously published artwork available when possible. Ship expansions with a new build, not a remote download service.

Before the production content session: review variety, repetition, category stopping conditions, and ongoing-rule duration. Agree on final copy and stable IDs before commissioning or generating artwork.

The supplied Sheet1 CSV (`Drink at Ron - Sheet1.csv`) has Main title/description columns and separate VIP title/description columns. `src/content/custom.ts` restores every nonblank Main row verbatim (blank row 75 and the description-less row 106 are excluded) into its own opt-in `house` pack (94 cards) or, for the 8 CABIIN rows, into Cabin weekend, and the four VIP rows into `vip`. IDs contain the 1-based sheet row number for audit, including duplicate headings. Rows that name dice (`4d6`, `1d20`, `2d6`, `1d6`) keep the app roll so the pour is computed; conditional rolls that the engine cannot resolve from one roll (the Game Giveth/Taketh multiplier) stay as written without a dice definition. Do not soften, rewrite, or add permission language to House copy: it is the supplied sheet and the sheet is the authority. The one owner-requested exception is the 2026-10-07 crude pass, which added a kicker to thirteen flat rows (listed in `reference/README.md`) and left every in-joke row alone. The 2026-09-26 logic pass made minimal clarity edits only where the sheet was ambiguous about who acts or how long a lasting rule lasts (`house.sheet-005`, `house.sheet-034`, `house.sheet-082`, `house.sheet-099`, and rows 40 and 53, now `cabin.first-name-only` and `cabin.abra-like-a-slut`); do not extend that beyond clear ambiguity or duration. The eight rows that are CABIIN board spaces (sheet rows 12, 16, 24, 28, 40, 42, 53 and 54) play in Cabin weekend instead, verbatim, as `cabin.maddy-booty`, `cabin.ursaring`, `cabin.wench`, `cabin.no-take-give`, `cabin.first-name-only`, `cabin.pet-that-dog`, `cabin.abra-like-a-slut` and `cabin.whinnie-the-pooh` (owner decision, 2026-10-05). No card belongs to two packs (a unit test enforces it). Preview every card in the workshop at small-phone width and enlarged text. An active game's saved snapshot is never rewritten by catalog changes.

Packs can optionally specify `artwork: 'art/your-pack.webp'`. The file must exist and follow the same local path rules as card artwork. Omit it to use the painted tankard. Shared pack controls and card frames are automatic; packs do not carry UI components, animation logic, or fonts.

## Card data and bulk review

A card is a title, a rules body, a category, and — for dice cards — a structured `dice` definition: `count`, `sides` (6 or 20), and either one `instruction` template or `outcomes` that cover every total exactly once. Outcome ranges accept an optional `step` (odds/evens), a top-level `doubles` instruction handles matching dice, and templates may use `{total}` plus `{first}`…`{fourth}` for per-die amounts. Every result must resolve to one exact instruction; a card that needs odds/evens or "otherwise" resolved at the table is a bug. Artwork defaults to the shared painted frame, and there is no illustration text to author. `roll()` and `rollTable()` in `author.ts` cover the common dice cases and `validateDice` enforces them at build time. When the roll is only one of two options ("do the dare, else drink 2d6"), wrap the definition in `choice(dice, skipLabel, rollLabel)`: the card then shows two plaques, the skip label puts the card aside unrolled and the roll label rolls. Labels are at most 14 characters; the rules copy stays as written.

For a human review pass, run `npm run cards:review`. It regenerates `docs/CARD_REVIEW.md` (readable table with a blank Review column) and `docs/card-review.csv` from the live catalog, so the sheet can never drift from what ships. Edit the source and regenerate; do not hand-edit either file. `src/content/sample.ts` holds the supplied sample set and assembles the `core` pack, `classics.ts` holds the classic / King's Cup basics, `standard-expansion.ts` holds the trimmed dice expansion, `custom.ts` holds the verbatim House deck plus the four VIP additions, `pokemon.ts` holds the Pokémon translation of the supplied board sheets, whose raw JSON stays in `reference/`, `cabin.ts` holds the CABIIN 2.0 translation (`reference/cabiin-2/`) plus the IDs of the House rows it shares, and `likely.ts` holds the Most Likely To vote prompts (one shared title and rule template; append prompts, never renumber). In production `catalog.ts` is a lazy chunk read through `registry.ts`, so a new pack costs lazy budget, not initial budget. New cards need an assignment in `src/content/imprint.ts` (the build and `tests/imprint.test.ts` require one); the content uses stable category motifs from the existing sprite.

## Optional illustration and pack identity

Per-card illustration briefs are retired. Every card renders in the shared painted frame with its deterministic imprint, and no artwork text is authored. If a specific scene is ever worth shipping, follow `ILLUSTRATION_GUIDELINES.md`, register it in `src/presentation/artwork.ts`, and pass its path as the optional `artwork` argument; the old dwarf direction stays rejected.

Each registered pack needs a distinct `logo`, such as `logo: 'art/packs/core.svg'`. Keep logo paths stable and add the file under public/art/packs; the build rejects missing files and reused logo paths. The same mark appears in setup, the pause legend, and card footers. The Core diamond is reserved for Core. Optional typing keeps older pack fixtures compatible, but release validation requires explicit logos for all registered packs.

A shared card shows marks for selected packs containing it, in catalog order. Marks follow the installed catalog as cosmetic metadata; they do not alter or rewrite a saved session. Stable namespaced IDs preserve the known origin's mark for retired cards in older saves. Unknown removed packs do not acquire an invented Core mark. Keep old pack metadata and logo assets available across releases when possible. Gameplay, snapshots, and shuffled order are unchanged.

## Pack quests (game modes)

A pack can bring a game mode: declare `quest: { mode, summary, label, goal, length, cardIds, finale }`. `cardIds` are quest-only cards, dealt only in that mode and never in the pack's plain deck (Pokémon's 24 gym leaders). A card's optional `ribbon` (at most 32 characters, e.g. "Gym Leader · Boulder Badge") renders as a gold banner over the rules with a gilded title; it costs a line of rule space, so keep ribbon cards' rules short. The setup screen shows `mode` and `summary` as a choice beside Standard/Infinite; choosing it holds the pack on (other packs can join) and plays without a card limit. Tag the cards that advance the meter with `quest: "<packId>"`; a tagged card adds one when it is put aside, reaching `goal` starts the finale. `finale` is a list of stages `{ label, pick, cardIds }`: when the game starts, each stage draws `pick` of its `cardIds` at random, and after the goal those cards are dealt one at a time, in stage order, between deck cards; the meter shows the stage label (and its count when `pick` is more than 1). Putting the last aside ends the game. `length` is the run's target: `goal` tagged cards are spread through its first draws (`paceQuest`), so the finale always lands by then. Author finale cards in the same module, in no deck list (validation enforces it), and include them in what the pack's loader returns. Validation requires at least `goal` tagged cards and `length > goal`. In the plain modes the pack's cards play as ordinary cards with no meter.

**Battles (since 2026-10-15).** A card with `battle: true` is a fight the table can lose; in a quest only a win counts. A dice battle marks its winning outcomes with `win: true` (and `doublesWin: true` when its doubles win); validation requires at least one winning and one losing result, and no `choice`. A battle without dice lands with Won and Lost plaques and the card takes no tap until one is picked, so write its rules to be judged on the spot (no "until your next turn") and to say what losing costs. A lost tagged card earns nothing and goes back into the rest of the deck, at least one card away, and the remaining tagged cards are re-paced so the run keeps its tempo. A lost finale card is replaced by another from its stage (one not already picked, never the one just lost when there is a choice), dealt next, until one is beaten. A lost dice battle greys its ribbon once the result is on the card. `win` and `doublesWin` are only allowed on battles. The League's gym leaders and Champions are battles; the Legendary and Elite Four are not.

## Crawls (Pub Crawl)

A quest with `party: { hearts }` is a crawl. Its `goal` is 0 and its stages are the whole run, dealt from the first card; stage cards may also be the pack's own deck cards (so they play as ordinary cards in the plain modes), and the mode plays its pack alone. Give the mode its own `mark` (a single-colour SVG under `art/packs/`).

- Rooms are stages with `pick` (eight a floor since 2026-10-17); a boss stage holds cards with `hits` (one of them is picked). The run's floors are the room stages; each boss closes one. A lone stage of one card that is neither a boss nor an omen nor a landing is a set piece (Pub Crawl's queue and closing time, the League's rival): the medallion and the party dialog name it by its label.
- A finale slot may be `{ oneOf: [[stages], [stages]] }`: one route is picked at random when the game starts and saved as the run's stages, so a depth can be one of several floors (Dungeon night: Cellar, Wine Cellar or Brewery; Catacombs, Sewers or Walk-in Freezer; Drowned Taproom, Kitchen or Rooftop Bar; each with its own rooms and bosses; Last Call closes every third floor). Stage labels must be unique across routes (the stage banner finds its `intro` by label).
- Set `encounter` on every crawl card (`monster`, `elite`, `ambush`, `trap`, `trial`, `relic`, `treasure`, `shrine`, `boss`, `merchant`, `fork`, `omen`, `rest`); the `dungeon/shared.ts` helpers do. An omen's `hurt` targets kinds, and a boss is told apart from an ambush only by it.
- An **ambush** is a room fight with `hits: 2`: it is dealt again, like a boss, until beaten twice, but it lifts no curse and a smoke bomb can't flee it. An **elite** is listed in its floor stage's `elite` (never in `cardIds`): it is dealt only when a fork's loud door swaps it in for the floor's next room. A fork is never dealt last on its floor.
- **Merchants and forks** carry `offers` (two or three plaques, labels at most 18 characters): `cost` (hearts paid outright, never the last one, no shield), `loot`, `heal`, or `elite: true` (the loud door). The card takes no tap; a plaque puts it aside. Write the drink price into the label ("Drink 3"); a heart price shows as a seal on the plaque. Offers are crawl-only: keep these cards out of the deck.
- **The run's omen** (`omen` on a card, `party.omen`) is the run's first stage (pick 1): the League's starter, Pub Crawl's adventurer. Its effect applies when it is put aside and holds for the run: `hearts` (starting and maximum), `loot` (into the satchel), `satchel` (its size), `hurt` (extra hearts per loss by encounter kind), `heal` (extra on every heal), `bossHits`, and the felt perks below. With `evolves` it grows (a League evolution, a Pub Crawl level).
- **Boons** (2026-10-17): a card's `boon: { name, rules, effect }` joins `party.boons` when the card is put aside (a battle only on a win; a boss or an ambush only when it falls) and holds the rest of the run. Boons stack with each other and with the run's omen (`stackEffects` in `engine.ts`): numbers add up, `crit` and `fumble` widen to the widest, and a boon's `satchel` moves the size by its difference from three (4 is one more slot, 2 one fewer). The party dialog lists every boon with its rules. Pub Crawl's tonight's omen (the second card) is a boon, and so is every trinket a boss or an elite drops (`trinket(name, effect)` in `dungeon/shared.ts` writes the rules from the numbers). Because they stack, write their words as changes ("two more hearts", "one more satchel slot"), never totals; `dungeonOmenWords.relative` does this for generated text. An empty effect is a table rule the app doesn't track. Omens and boons may name hearts and items: they never play in the plain modes (a trinket on a deck card is ignored there). Give every omen and trinket a trade-off or a small, felt edge, and check the win rates in the test output.
- **Spoils** (2026-10-17): a boss or an elite carries `spoils` (two boons, built by `drops: [trinket(...), trinket(...)]` in `dungeon/shared.ts`) instead of a single `boon`: its signature trinket and a contrasting alternative (offence against defence). On the winning roll that fells it, the card shows one plaque per trinket and takes no tap; the pick puts it aside (`awaitingSpoils`, `takeSpoils`) and is kept as `<card id>#<index>` in `party.boons`. In the plain modes spoils are ignored.
- **Bar Tab / Baton Pass** (`round`, 2026-10-17): on a lost roll the drawer passes that fight's drinks to someone else (the party still loses the hearts), once per draw (`party.passed`). Sold by a few merchants and found in the Sewers.
- **Jinxes** (2026-10-17): a card's `jinx: { name, rule }` (name at most 22 characters, rule at most 110) is a spoken table rule the app keeps, like a Picolo virus: it lands when the card is put aside (a battle only when lost), replaces any jinx before it, shows on the meter, in the party dialog and in a banner, and lifts when the floor's boss falls. Write the rule for "the jinxed player" (whoever drew the card), "everyone" or "nobody", ending on a one-drink slip ("Forget: drink 1."), and hold it to the table-rule test in `docs/CARD_VOICE_REFERENCE.md` (no props, a laugh or a gotcha, no chores). The best jinxes give the table something to catch (No First Names, Question Master, Thumb Master, Mean Look). Since 2026-10-17 the League lays them too (Agatha, Hop, Giratina, Psyduck, Haunter, Team Rocket, Mars), lifted by the next boss.
- **Push your luck** (`press: { prizes }`, `gamble` in `dungeon/shared.ts`, 2026-10-17): a single-d20 battle whose win banks the next prize and shows Cash out / Again plaques (`awaitingPress`, `pressOn`, `cashOut`); each Again rolls `PRESS_STEP` (2) lower; a loss forfeits everything banked, costs its heart and pours into the Cup. The last prize cashes out on a tap. Counted as a relic for roll bonuses; one per floor.
- **Hidden rooms** (`dungeon/bookcase.ts`, 2026-10-17): a `oneOf` slot between the first landing and the second floor, each route a guards stage (pick 2 of 3, `guard`) and a keeper stage (`keeper`: a 2-hit boss with spoils and an optional jinx). The keeper's fall lifts the curse and jinx and brings the Quaff back like any boss. Seed tests with four route draws (three floors and the room).
- **Landings** (`encounter: "rest"`) sit between Pub Crawl's floors: two offers, level the adventurer up for drinks (`evolve: true`) or rest (`heal`). Each landing stage has its own pool, so the two in a run are never the same card.
- **The Quaff and the Cup** are quest settings, not cards: `party: { hearts, quaff, cup }`. With `quaff: n` a lost single-d20 fight can be rolled again for n drinks, once until the next boss falls (a hex does not seal it). With `cup: true` every lost fight (a missed boss swing too) adds a splash to `party.cup`, and the end screens say who drinks it.
- `battle: true` cards take `damage` (1 to 5 hearts lost on a loss). `hits` (1 to 5) makes a boss: each deal is one swing, the boss is dealt again, win or lose, until it has taken its hits, and its fall lifts the floor's curse.
- `reward: { loot }` adds an item to the satchel (at most three; a fourth is left behind) and `reward: { heal }` restores hearts (never past the start). A battle's reward comes only on a win; any other card's when it is put aside. `curse` is set by a lost battle, or by putting aside any other card; it lasts until the floor's boss falls.
- A choice battle (`dice.choice` on a battle) is a relic: the skip option walks away, neither won nor lost.
- **Natural 20 and natural 1** (owner, 2026-10-17, both crawls). On a single d20, a 20 doubles what a win brings and a 1 doubles what a loss costs. The engine does the hearts, items and boss swings (`natural` in `engine.ts`: a heal and an item come twice, a boss takes two hits, a loss costs double hearts before a shield or bleed). The text is `src/content/naturals.ts`: `withNaturals` splits face 20 off a winning range and face 1 off a losing one and writes "Natural 20! …" with the gives doubled (and anything "drinks", "they drink", "or drink", a shot, a stolen sip, a rule) or "Natural 1! …" with every drink, shot and finish doubled ("Finish your drink, then a fresh one"). A table whose 20 or 1 is already its own outcome keeps it, with the lead added. `tests/naturals.test.ts` fails a natural that reads like the roll beside it; give that card its own `crit` or `fumble` (a `{total}` loss always needs one). Write win text with the gives in it, and loss text with the drawer's drinks, so the doubling lands. Outside the crawls (owner follow-up, same day) the rule is text only: a d20 card's own 1 and 20 outcomes lead with "Natural 1!" and "Natural 20!" (Fuck Around, Nat One, Missingno's 1). Cards where the roll is the amount (God's Drunkest Soldier, Body Count, House row 8, Maddy Booty) have no good or bad end and stay as written; `tests/naturals.test.ts` lists them.
- Never write hearts, items or curses into the rules: the card's seals show them in a crawl, and the plain modes would show nonsense. Write the drink instead (the drawer still drinks on a loss). Keep fight rules near 80 characters, since a Flee or Reroll plaque can cover the card's foot.
- Tune with the constants in `dungeon/shared.ts`, not card by card, and keep `tests/dungeon.test.ts` passing: it plays 4,000 seeded runs through the real engine, holds the win rate between 18% and 40% and a won run between 38 and 55 draws, holds every adventurer, omen and route between 10% and 50%, keeps the Plus-One (the worst adventurer by design, 600 forced runs) between 1% and 10% and below every other, and checks that most adventurers level up without most reaching level 3. It prints the rate for each, so a new card shows its effect at once.

## Pokémon League (a journey crawl)
Since 2026-10-16 the League is a crawl like Pub Crawl, and everything in the section above applies. Its cards live in `src/content/league/` and `pokemon-league.ts`:
- **Starters** (`starters.ts`) are omens that may carry `evolves`: one or two later forms, each `{ title, omen }`, whose effect *replaces* the one before (write each form's effect in full, hearts relative to the run's base). Since 2026-10-17 the power text is written from the numbers (`describeOmen` in `src/game/omenText.ts`, through `starter` in `journey.ts`): write only a short flavor sentence (the card adds "Max HP 15. Every heal heals 1 more. Starts with a Potion."), and the team dialog shows the current form's name and power. The evolution banner says what changed (`describeChange`: "Max HP 15 → 17. Gets a Potion."), and the evolve plaque names the next form. Give each starter one signature, make every evolution a visible upgrade, and keep `tests/starters.test.ts` passing: no two starters share a power line, and no evolution changes nothing.
- **Felt perks** (2026-10-17): an omen's `roll` adds to single-d20 battle rolls (`all` or by kind), `crit`/`fumble` widen the natural range, `reroll20` throws away every 20, and `restock` returns an item at every gym. Roll bonuses are strong (one point moves a run's win rate by several points); measure every change in `tests/league.test.ts`. Bidoof is the worst starter by design and has its own forced-run test.
- **Dice palettes**: every starter form and every Pub Crawl adventurer level carries `palette: { primary, secondary }` (the `PALETTES` maps in `starters.ts` and `dungeon/classes.ts`): the body colour as enamel and the accent as metal. Since 2026-10-17 tonight's omen is a boon and no longer colours the dice. `tests/dice-palette.test.ts` holds the numerals at 4.5:1 and every pair distinct.
- **League items.** Besides Potion, Protect, X Attack and Escape Rope, two items come only from starters (2026-10-17): a **Revive** (`revive`) saves one white-out, back to half max HP, on its own (a Confused, sealed bag keeps it shut); a **Rare Candy** (`candy`) is used from the bag to evolve the starter now (never Eevee, which picks its form on an evolution card). Since 2026-10-17 Dungeon night deals them too, as Second Wind and the Dog-Eared Tome (a level up now), from adventurers, merchants and trinkets.
- **Branching starters** (`branches: true`, Eevee) list up to three alternative forms in `evolves`; the evolve plaque splits into one plaque per form (four across with Press B) and `takeOffer`'s `branch` picks it. A branching starter evolves once.
- **Evolution cards** carry an offer with `evolve: true` (validated on any crawl card); the engine refuses it once the starter is fully evolved, so pair it with a "Press B" heal plaque.
- **Routes** (`routes.ts`) use the helpers in `journey.ts`: `wild`, `trainer`, `challenge` (Won/Lost), `hazard`, `catchable` (offers: a drink for a ball and HP back, or let it go), `gamble`, `item`, `center`, `mart`, `crossroads` and `ace` (the route's elites), `evolution`, `rival`, `grunt` and `villain`. Each route is its own pool: no card is in two stages.
- **How a fight rolls** (2026-10-17 variety pass): every fight helper takes a `Roll`, a function of the card's need, so the tuning constants retune all of them. `vs(lose, win, { crit, fumble })` is a d20. `moves(lose[], win[])` is six named moves on a d6, worst first; `lose` must hold exactly `sixLoses(need)` faces (the d20 odds rounded to sixths), and a retune that moves the split throws at load, so the faces get rewritten rather than silently flipping. `pair(lose, win, doubles?)` is 2d6 at the total nearest the odds (`pairNeed`); its doubles always win, so open them with "A pair!" (the word "doubles" is banned from results). Mix them: a route should not read as a column of "Drink 3 / Give 3". Good outcomes name a target (the worst flapper, whoever drove here, the player you poked), hand out a short status that lasts until the drawer's next turn, a dare with a drink as the alternative, a graded `{total}` loss, or a pair of players.
- **Gyms**: `gymTiers[k]` is every region's (k+1)th gym; a new region adds one leader to each tier. Every League boss is a `battle` with `encounter: "boss"` and `hits`/`damage` from `league/shared.ts`; leaders keep `quest: "pokemon"`, which counts them as badges. A boss's dice should win near the tier's odds: a 2-hit Legendary at 5% (as Mewtwo once was) makes a run unwinnable.
- Tune with the constants, never card by card, and keep `tests/league.test.ts` passing; it prints each starter's and hideout's win rate.

## Secrets and timers

A card may carry a `secret` (at most 120 characters) or a `timer`, or both, but never with `dice`. Validation lives in `src/content/validate.ts` and `src/game/timer.ts`.

- **Secret.** The face shows the public `rules`; a "Hold to read" plaque swaps the rules for the secret while a finger holds it and hides it on release (keyboard and VoiceOver activation toggle it instead). The rules must say who reads it ("Left neighbor reads alone", "Read alone"). A secret of 24 characters or fewer prints large, for words the table reads across the room (Forehead).
- **Never pass the phone on a timer.** A fuse card keeps the phone on the table and passes a beer (the plaque reads "phone stays put"); its `end` names whoever is holding the beer. Handing the phone to one neighbor to read a secret is fine; tossing it round a table is not (owner, 2026-10-06).
- **Timer.** `{ version: 1, kind: "fuse", min, max, end }` burns for a hidden whole number of seconds in `min`..`max` (5 to 90); `{ version: 1, kind: "countdown", seconds, end }` counts down in view (3 to 120). A plaque starts it ("Light the fuse" / "Start the clock", so fuse rules open with "Light the fuse" and clock rules say "Start the clock"); the card can't be put aside with a tap until time is up (a quiet Skip plaque puts it aside at any point, lit or not), when a full-screen BOOM or TIME flashes and `end` (at most 120 characters) replaces the rules. Write `end` as the full consequence. Timers are display state only: nothing is saved, and a reload leaves the card unlit.
- Plaques cover the foot of the card, so keep these rules near 90 characters; at 375×667 and larger every Secrets & fuses card fits without a scroll (2026-10-06 sweep).
