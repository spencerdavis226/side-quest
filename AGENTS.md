## Constraints

- Preserve the approved painted frame and constant 2:3 outer ratio (front/back/Previous Card agree). Stationary taps must keep working while long rules stay scrollable.
- Minimum platform: iOS/iPadOS 16 Safari (container query units, `cqw`, need 16.0); `vite.config.ts` builds for `safari16`. Do not use CSS or APIs newer than that without a fallback.
- Keep assets local and GitHub Pages/offline compatible — no CDN or runtime services.
- `reference/` holds raw user-supplied sources (CABIIN sheet, house Sheet1 CSV, sample deck JSON). Keep them exactly as supplied and out of `src/` and the bundle; replace with a newer supplied file and rerun the matching `npm run *:reference` parse instead of editing them to match shipping content.
- Saved games must survive every update. `tests/fixtures/saves/` holds real saves frozen from seeded games (`npm run fixtures:saves`), and `tests/save-fixtures.test.ts` requires each to load and play on. A change to what a save holds, to `parseSession`/`validateParty`/`validateRoll`, or to the runtime card rules in `src/content/validate.ts` adds fixtures for the new state (the script writes `<date>-<situation>.json` and never rewrites a file); never edit or delete a fixture to make the test pass. A save that still fails to load is copied to `side-quest.session.corrupt.v1` before the recovery screen clears it.
- Merge, push, and publication need explicit user authorization; ordinary local edits/checks do not.

## Commands (Node 22.12+, `npm ci`)

```sh
npm run dev            # vite on 127.0.0.1; no service worker — offline needs a production build/preview
npm run dev:phone      # vite on 0.0.0.0; open the printed Network URL from a phone on the same Wi-Fi (HTTP: no service worker/offline)
npm test               # vitest unit tests (about 8 s); skips the balance simulations
npm run test:balance   # tests/*.balance.test.ts: 4,000 seeded crawl and League runs (about 2 min)
npm run lint           # eslint: typescript-eslint + react-hooks rules
npm run typecheck      # tsc -b over src, scripts, tests and *.config.ts
BASE_PATH=/side-quest/ npm run build    # validate-content -> tsc -b -> vite -> check-budget
npx playwright install chromium webkit
CI=1 BASE_PATH=/side-quest/ TEST_PORT=4398 npm run test:e2e -- --workers=2
CI=1 BASE_PATH=/side-quest/ TEST_PORT=4398 npm run test:release -- --workers=2
BASE_PATH=/side-quest/ npm run test:update   # two-build update/PWA flow
npm run test:workshop  # dev server on :5175
```

- Playwright specs (`*.spec.ts`) are not run by `npm test`. E2E serves `dist` through `npm run preview`; build first. Locally `reuseExistingServer` is on, so a stale preview on the default `:4173` will silently serve an old build — set `TEST_PORT`.
- `?workshop=1` and `npm run test:workshop` use the dev server, not `dist`; workshop code must never reach production.
- CI (`.github/workflows/pages.yml`) runs unit tests -> lint -> build in one job and the balance simulations in a parallel job (a deploy waits for both), then the tagged release smoke suite in parallel jobs, one Chromium and three WebKit shards, WebKit one test at a time (each installs only its browser, with binaries cached per Playwright version; the update test runs in the Chromium job) against that same `dist`, builds with `BASE_PATH=/side-quest/`, and deploys `dist` to Pages only from `main`. Pushes that change only Markdown or `docs/` skip the pipeline (and so don't deploy). Full production E2E and exhaustive workshop sweeps remain available through a manual workflow dispatch with `full_validation` enabled. Run them after layout/engine changes or for a dedicated card review, not on every publish.

Standing rule in both crawls (owner, 2026-10-17): on a single d20 a natural 20 doubles a win's heal, item and boss swing, and a natural 1 doubles a loss's hearts (`natural` in `engine.ts`); `src/content/naturals.ts` writes the doubled drinks into each card's 20 and 1 outcomes. Difficulty is measured by `tests/dungeon.balance.test.ts` (`npm run test:balance`, not part of `npm test`), which plays 4,000 seeded runs; keep its win rate between 18% and 40%, and every adventurer, omen, hidden room and floor between 10% and 50% (the joke classes, the Plus-One, the Intern and the Mimic, worst by design, between 1% and 10%), when changing crawl cards or rules (a class levels up along one line of two levels); tuning lives in `src/content/dungeon/shared.ts`.
