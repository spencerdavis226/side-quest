# Side Quest — agent entry point

Read `docs/STATUS.md` before planning or editing. It is the single current handoff (evidence, approved constraints, next task); it supersedes historical plans/study notes, and direct user instructions take precedence. Update it in place at handoff with changed files, commit, verification, risks, and next task — do not add competing plan documents.

## Constraints

- Work on `main` (the only active branch; every push to it deploys). Preserve HEAD and all untracked work; never discard work in progress.
- Work on one assigned task at a time; do not repeat completed milestones or replace the stack on your own.
- Keep the pure engine (`src/game`) and saved outcomes independent of rendering. Preserve session schema v2 + v1 migration and the `side-quest.session.v1` storage key (pre-rename `drink-at-ron.*` keys are moved by `migrateStorageKeys`; keep that path); rendering changes must not force a migration.
- Preserve the approved painted frame and constant 2:3 outer ratio (front/back/Previous Card agree). Stationary taps must keep working while long rules stay scrollable.
- Minimum platform: iOS/iPadOS 16 Safari (container query units, `cqw`, need 16.0); `vite.config.ts` builds for `safari16`. Do not use CSS or APIs newer than that without a fallback.
- Keep assets local and GitHub Pages/offline compatible — no CDN or runtime services.
- `reference/` holds raw user-supplied sources (CABIIN sheet, house Sheet1 CSV, sample deck JSON). Keep them exactly as supplied and out of `src/` and the bundle; replace with a newer supplied file and rerun the matching `npm run *:reference` parse instead of editing them to match shipping content.
- Saved games must survive every update. `tests/fixtures/saves/` holds real saves frozen from seeded games (`npm run fixtures:saves`), and `tests/save-fixtures.test.ts` requires each to load and play on. A change to what a save holds, to `parseSession`/`validateParty`/`validateRoll`, or to the runtime card rules in `src/content/validate.ts` adds fixtures for the new state (the script writes `<date>-<situation>.json` and never rewrites a file); never edit or delete a fixture to make the test pass. A save that still fails to load is copied to `side-quest.session.corrupt.v1` before the recovery screen clears it.
- Merge, push, and publication need explicit user authorization; ordinary local edits/checks do not.

## Commands (Node 22.12+, `npm ci`)

```sh
npm run dev            # vite on 127.0.0.1; no service worker — offline needs a production build/preview
npm run dev:phone      # vite on 0.0.0.0; open the printed Network URL from a phone on the same Wi-Fi (HTTP: no service worker/offline)
npm test               # vitest unit tests (about 8 s); skips the balance simulations
npm run test:balance   # tests/*.balance.test.ts: 4,000 seeded crawl and League runs (about 2 min)
npm run lint           # eslint: typescript-eslint + react-hooks rules
npm run typecheck      # tsc -b over src, scripts, tests and *.config.ts
BASE_PATH=/side-quest/ npm run build    # validate-content -> tsc -b -> vite -> check-budget
npx playwright install chromium webkit
CI=1 BASE_PATH=/side-quest/ TEST_PORT=4398 npm run test:e2e -- --workers=2
CI=1 BASE_PATH=/side-quest/ TEST_PORT=4398 npm run test:release -- --workers=2
BASE_PATH=/side-quest/ npm run test:update   # two-build update/PWA flow
npm run test:workshop  # dev server on :5175
```

- Playwright specs (`*.spec.ts`) are not run by `npm test`. E2E serves `dist` through `npm run preview`; build first. Locally `reuseExistingServer` is on, so a stale preview on the default `:4173` will silently serve an old build — set `TEST_PORT`.
- `?workshop=1` and `npm run test:workshop` use the dev server, not `dist`; workshop code must never reach production.
- CI (`.github/workflows/pages.yml`) runs unit tests -> lint -> build in one job and the balance simulations in a parallel job (a deploy waits for both), then the tagged release smoke suite in parallel jobs, one Chromium and three WebKit shards, WebKit one test at a time (each installs only its browser, with binaries cached per Playwright version; the update test runs in the Chromium job) against that same `dist`, builds with `BASE_PATH=/side-quest/`, and deploys `dist` to Pages only from `main`. Pushes that change only Markdown or `docs/` skip the pipeline (and so don't deploy). Full production E2E and exhaustive workshop sweeps remain available through a manual workflow dispatch with `full_validation` enabled. Run them after layout/engine changes or for a dedicated card review, not on every publish.

## Budgets and dice prototype

- `scripts/check-budget.ts` enforces release budgets on `dist`: each lazy JS chunk ≤ 200 KiB gzip (per chunk since 2026-10-16, owner decision; it capped the sum of all lazy chunks before), runtime ≤ 4 MiB (raised from 3 MiB on 2026-10-15, owner decision), any image ≤ 500 KiB, no workshop strings in production, and no card text in the initial chunk. Initial (critical-path) JS is reported but has no cap since 2026-10-05 (owner decision; the first screen is dominated by art and fonts). "Initial" = chunks referenced by `dist/index.html`; everything else is lazy. Heavy optional features (e.g. the dice library) belong in lazy chunks, not the initial tier. Measure the built output instead of guessing, and do not change limits without user approval.
- The full-screen `@3d-dice/dice-box-threejs` overlay is the default dice renderer (`src/components/FullScreenDice.tsx`, adapter `src/presentation/dice/library.ts`); it is lazy-loaded and must be fed predetermined results from `src/game/dice.ts`. The catalog has eight opt-in packs: the generated main deck (`src/content/{sample,classics,standard-expansion}.ts`: 96 cards), the supplied Sheet1 House deck (`src/content/custom.ts`: 94 cards, restored verbatim from the raw sheet kept at `reference/Drink at Ron - Sheet1.csv`; its 8 CABIIN rows play in Cabin weekend), `VIP night` (`src/content/vip.ts` + the four `vip.sheet-*` entries in `custom.ts`: 16 cards), and the Pokémon board-sheet translation (`src/content/pokemon.ts`: 120 cards morphed from `reference/pokemon_board_spaces.json` with the source consequences kept as written, plus 356 League-only cards: 72 gym leaders and the 79-card gauntlet in `pokemon-league.ts` and `league/<region>.ts`, and the starters, routes and hideouts in `league/`), and `Cabin weekend` (`src/content/cabin.ts`: 85 cards, translated from the CABIIN 2.0 sheet in `reference/cabiin-2/` plus the sheet's 8 CABIIN rows verbatim; no card is in two packs), `Most Likely To` (`src/content/likely.ts`: 250 standalone vote cards), `Secrets & fuses` (`src/content/secrets.ts`: 150 cards with a hold-to-read `secret` and/or a `timer`, fuse or countdown; display state only, never saved; see `docs/AUTHORING.md`), and `Dungeon night` (`src/content/dungeon.ts` assembling `src/content/dungeon/`: 245 cards in every mode plus 162 Pub Crawl-only finds, gambles, merchants, forks, landings, omens, adventurers, rival-party and hidden-room cards). A quest with `party: { hearts }` is a crawl (Pub Crawl): `goal` 0, its stages are the whole run from the first card (rooms may also be deck cards; a finale slot may be `{ oneOf: [[stages], ...] }`, one route picked per game, so each depth is one of several floors), the pack plays alone, and the table shares hearts in `quest.party` (optional, schema v2 unchanged): `damage` on a lost battle, boss `hits` (dealt again until it falls), `reward` (satchel `loot`, at most 3, or `heal`) and `curse` (to the end of the floor). Zero hearts wipes the party and ends the game. Standing rule in both crawls (owner, 2026-10-17): on a single d20 a natural 20 doubles a win's heal, item and boss swing, and a natural 1 doubles a loss's hearts (`natural` in `engine.ts`); `src/content/naturals.ts` writes the doubled drinks into each card's 20 and 1 outcomes. A run opens on an `omen` card (its typed effect, saved as `party.omen`, holds for the run; Pub Crawl's is the adventurer, which levels up at landings like a starter evolves). Since 2026-10-17 cards may carry a `boon` (tonight's omen, trinkets from bosses and elites; stacked in `party.boons` by `stackEffects`) and a `jinx` (a spoken rule in `party.jinx` until the floor's boss falls), and Pub Crawl's quest sets `party.quaff` (a lost d20 rerolled for drinks, once until a boss falls) and `party.cup` (a splash per lost fight); all optional, schema v2 unchanged. Merchants and forks put themselves aside only through their `offers` plaques (a fork's loud door swaps the floor's next room for one of its `elite` cards); an ambush is a room with `hits: 2`; `encounter` names a card's kind (bosses are told from ambushes by it). Difficulty is measured by `tests/dungeon.balance.test.ts` (`npm run test:balance`, not part of `npm test`), which plays 4,000 seeded runs; keep its win rate between 18% and 40%, and every adventurer, omen, hidden room and floor between 10% and 50% (the Plus-One, worst by design, between 1% and 10%), when changing crawl cards or rules; tuning lives in `src/content/dungeon/shared.ts`. Card text loads per pack: the app imports only `src/content/manifest.generated.ts` (pack metadata and card IDs, regenerated by `npm run content:manifest` and at the start of `npm run build`; a unit test fails if it is stale) and fetches a pack's cards through `src/content/loaders.ts` when a game starts (warmed while setup is open; a resumed game uses its saved snapshot). Never import `content/catalog.ts` or a content module statically from app code; `check-budget.ts` fails the build if card text reaches the initial chunk. A new pack needs a loader entry. `validateCatalog` lives in `src/content/validate.ts`. A pack may declare a `quest`, which becomes a game mode on the setup screen beside Standard/Infinite (`mode`, `summary`, meter `label`, `goal`, run `length`, quest-only `cardIds` dealt only in that mode, and `finale` stages, each `{ label, pick, cardIds }`, whose cards are kept out of both lists). Choosing it sets `config.quest` (no card limit) and holds the pack on; cards with `quest: <packId>` advance the meter when put aside (a `battle` card only when won; a lost one goes back into the deck, and a lost finale card is replaced by another from its stage until one is beaten), reaching the goal deals the finale: the stages' picks (made at random when the game starts and saved in `quest.finale`) are dealt one at a time between deck cards, and putting the last aside ends the game. `paceQuest` spreads `goal` tagged cards through the first `length` draws. In the plain modes those cards are ordinary (`src/game/engine.ts`; session field `quest`, optional so v2 saves without it still load). Pokémon's mode is Pokémon League, a crawl since 2026-10-16 (owner): it plays the Pokémon pack alone with shared Team HP (`party.hearts` 17). A run opens on a starter (1 of 17 omens in `league/starters.ts`; an omen may carry `evolves`, one or two later forms, or with `branches` up to three alternatives the table picks between (Eevee), and an offer with `evolve` moves `party.form` on, the form's effect replacing the last), then eight routes of 4 cards from each route's 15 (`league/routes.ts`: wild Pokémon, trainers, hazards, catches (`heal` offers), items, a Pokémon Center, a Poké Mart, a crossroads with two Ace Trainers, and on five routes an evolution card), each closed by a gym from its tier (`gymTiers` in `pokemon-league.ts`: tier k holds every region's kth gym, 9 regions, so gyms are random but ramp up), a villain hideout after the fourth gym (`oneOf` 9 teams in `league/hideouts.ts`: 2 grunts, then a 2-hit boss), Victory Road, the rival (an ambush), a Legendary (1 of 30, 2 hits), 4 of 36 Elite Four and a Champion (1 of 13, 3 hits). Leaders keep `quest: "pokemon"`, which marks them as badges in the team dialog (`questRecord().badges`); `crawlTheme.ts` gives the League its words (Team HP, Bag, Potion, Protect, X Attack, Escape Rope, Poisoned, Confused, Whited out, Hall of Fame) and marks. Starter powers are written from their numbers (`src/game/omenText.ts`); only starters bring the Revive and Rare Candy items. Tuning lives in `league/journey.ts` (routes, hideouts, rival) and `league/shared.ts` (gyms and the gauntlet); `tests/league.balance.test.ts` plays 4,000 seeded runs and holds the win rate between 18% and 40%, every starter and hideout between 10% and 50%, a won run at 60 to 70 draws, and 70% to 90% of runs evolving at least once (30% to 50% to the final form). Old meter-mode League saves (no `party`) still load and play to their end; that engine path stays. A stage's optional `intro` sweeps across as a banner (`StageBanner`) when its first card is dealt, and an evolution sweeps its own (`EvolutionBanner`). A card's optional `ribbon` (≤ 32 characters) renders as a banner with a tinted title, gold unless `ribbonTone` is `pearl`, `violet` or `crimson`. Cards are authored as title + rules + category + optional dice, with no illustration text. Every dice card must resolve to one exact computed instruction (outcomes by total, optional `step` for odds/evens, `doubles`, and `{total}`/`{first}`…`{fourth}` placeholders); keep legacy `instruction` prose resolution for old saves. Keep engine/state contracts and saved-order behavior unchanged. Do not reintroduce a second renderer, and do not change per-body damping/sleep between the library's pre-simulation and its replay — that diverges the forced face.
- The approved front is `src/presentation/art/ornate-teal-frame.webp`, with live titles/rules and plain parchment (no scene illustration or imprint lattice). Preserve legacy `artwork` fields and the resolver for saved content/validation compatibility; do not reintroduce them in CardFace.
