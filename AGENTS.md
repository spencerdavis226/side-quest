## Constraints

- Work on `main` (the only active branch; every push to it deploys). Preserve HEAD and all untracked work; never discard work in progress.
- Work on one assigned task at a time; do not repeat completed milestones or replace the stack on your own.
- Keep the pure engine (`src/game`) and saved outcomes independent of rendering. Preserve session schema v2 + v1 migration and the `side-quest.session.v1` storage key (pre-rename `drink-at-ron.*` keys are moved by `migrateStorageKeys`; keep that path); rendering changes must not force a migration.
- Preserve the approved painted frame and constant 2:3 outer ratio (front/back/Previous Card agree). Stationary taps must keep working while long rules stay scrollable.
- Keep assets local and GitHub Pages/offline compatible — no CDN or runtime services.
- `reference/` holds raw user-supplied sources (CABIIN sheet, house Sheet1 CSV, sample deck JSON). Keep them exactly as supplied and out of `src/` and the bundle; replace with a newer supplied file and rerun the matching `npm run *:reference` parse instead of editing them to match shipping content.
- Merge, push, and publication need explicit user authorization; ordinary local edits/checks do not.

## Commands (Node 22.12+, `npm ci`)

```sh
npm run dev            # vite on 127.0.0.1; no service worker — offline needs a production build/preview
npm run dev:phone      # vite on 0.0.0.0; open the printed Network URL from a phone on the same Wi-Fi (HTTP: no service worker/offline)
npm test               # vitest; only tests/**/*.test.ts (unit)
BASE_PATH=/side-quest/ npm run build    # validate-content -> tsc -b -> vite -> check-budget
npx playwright install chromium webkit
CI=1 BASE_PATH=/side-quest/ TEST_PORT=4398 npm run test:e2e -- --workers=2
CI=1 BASE_PATH=/side-quest/ TEST_PORT=4398 npm run test:release -- --workers=2
BASE_PATH=/side-quest/ npm run test:update   # two-build update/PWA flow
npm run test:workshop  # dev server on :5175
```

- Playwright specs (`*.spec.ts`) are not run by `npm test`. E2E serves `dist` through `npm run preview`; build first. Locally `reuseExistingServer` is on, so a stale preview on the default `:4173` will silently serve an old build — set `TEST_PORT`.
- `?workshop=1` and `npm run test:workshop` use the dev server, not `dist`; workshop code must never reach production.
- CI (`.github/workflows/pages.yml`) runs unit tests -> build -> the tagged Chromium/WebKit release smoke suite -> update test, builds with `BASE_PATH=/side-quest/`, and deploys `dist` to Pages only from `main`. Full production E2E and exhaustive workshop sweeps remain available through a manual workflow dispatch with `full_validation` enabled. Run them after layout/engine changes or for a dedicated card review, not on every publish.

## Budgets and dice prototype

- `scripts/check-budget.ts` enforces release budgets on `dist`: lazy feature JS ≤ 200 KiB gzip, runtime ≤ 3 MiB, any image ≤ 500 KiB, no workshop strings in production, and no card text in the initial chunk. Initial (critical-path) JS is reported but has no cap since 2026-10-05 (owner decision; the first screen is dominated by art and fonts). "Initial" = chunks referenced by `dist/index.html`; everything else is lazy. Heavy optional features (e.g. the dice library) belong in lazy chunks, not the initial tier. Measure the built output instead of guessing, and do not change limits without user approval.
- The full-screen `@3d-dice/dice-box-threejs` overlay is the default dice renderer (`src/components/FullScreenDice.tsx`, adapter `src/presentation/dice/library.ts`); it is lazy-loaded and must be fed predetermined results from `src/game/dice.ts`. The catalog has seven opt-in packs: the generated main deck (`src/content/{sample,classics,standard-expansion}.ts`: 105 cards), the supplied Sheet1 House deck (`src/content/custom.ts`: 94 cards, restored verbatim from the raw sheet kept at `reference/Drink at Ron - Sheet1.csv`; its 8 CABIIN rows play in Cabin weekend), `VIP night` (`src/content/vip.ts` + the four `vip.sheet-*` entries in `custom.ts`: 16 cards), and the Pokémon board-sheet translation (`src/content/pokemon.ts`: 120 cards, plus 24 League-only gym leaders in `pokemon-league.ts`, morphed from `reference/pokemon_board_spaces.json` with the source consequences kept as written), and `Cabin weekend` (`src/content/cabin.ts`: 85 cards, translated from the CABIIN 2.0 sheet in `reference/cabiin-2/` plus the sheet's 8 CABIIN rows verbatim; no card is in two packs), `Most Likely To` (`src/content/likely.ts`: 250 standalone vote cards), and `Secrets & fuses` (`src/content/secrets.ts`: 150 cards with a hold-to-read `secret` and/or a `timer`, fuse or countdown; display state only, never saved; see `docs/AUTHORING.md`). Card text loads per pack: the app imports only `src/content/manifest.generated.ts` (pack metadata and card IDs, regenerated by `npm run content:manifest` and at the start of `npm run build`; a unit test fails if it is stale) and fetches a pack's cards through `src/content/loaders.ts` when a game starts (warmed while setup is open; a resumed game uses its saved snapshot). Never import `content/catalog.ts` or a content module statically from app code; `check-budget.ts` fails the build if card text reaches the initial chunk. A new pack needs a loader entry. `validateCatalog` lives in `src/content/validate.ts`. A pack may declare a `quest`, which becomes a game mode on the setup screen beside Short/Long/Infinite (`mode`, `summary`, meter `label`, `goal`, run `length`, quest-only `cardIds` dealt only in that mode, and `finale` stages, each `{ label, pick, cardIds }`, whose cards are kept out of both lists). Choosing it sets `config.quest` (no card limit) and holds the pack on; cards with `quest: <packId>` advance the meter when put aside, reaching the goal deals the finale: the stages' picks (made at random when the game starts and saved in `quest.finale`) are dealt one at a time between deck cards, and putting the last aside ends the game. `paceQuest` spreads `goal` tagged cards through the first `length` draws. In the plain modes those cards are ordinary (`src/game/engine.ts`; session field `quest`, optional so v2 saves without it still load). Pokémon's mode is Pokémon League: the 24 Gen 1–3 gym leaders (`src/content/pokemon-league.ts`, League-only, harder by design, each with a gold `ribbon` naming its badge) earn badges; 8 within 40 draws, then the gauntlet: 1 of 8 Legendaries, 4 of 9 Elite Four members, 1 of 3 Champions. The meter shows the stage (Legendary, Elite Four 2/4, Champion) and opens the badge case (`QuestRecord`, derived by `questRecord` from the save, never spoiling undealt picks); a stage's optional `intro` sweeps across as a banner (`StageBanner`) when its first card is dealt; beating the finale shows the Hall of Fame on the completion screen. A card's optional `ribbon` (≤ 32 characters) renders as a banner with a tinted title, gold unless `ribbonTone` is `pearl`, `violet` or `crimson`. Cards are authored as title + rules + category + optional dice, with no illustration text. Every dice card must resolve to one exact computed instruction (outcomes by total, optional `step` for odds/evens, `doubles`, and `{total}`/`{first}`…`{fourth}` placeholders); keep legacy `instruction` prose resolution for old saves. Keep engine/state contracts and saved-order behavior unchanged. Do not reintroduce a second renderer, and do not change per-body damping/sleep between the library's pre-simulation and its replay — that diverges the forced face.
- The approved front is `src/presentation/art/ornate-teal-frame.webp`, with live titles/rules and plain parchment (no scene illustration or imprint lattice). Preserve legacy `artwork` fields and the resolver for saved content/validation compatibility; do not reintroduce them in CardFace. Bundled frame surfaces live only in `src/presentation/frame-surfaces.ts`; do not restore an eager glob of `presentation/art`.
